# 職事文摘導覽

<https://soaring0616.github.io/digest/>

把《職事文摘》八十期的**篇題**和它背後**那一本書**對起來。
一次只給一篇：一個題目、它的讀經經節、它出自哪一本書的第幾篇，
然後一條簡單的超連結回臺灣福音書房。

起因是想用文摘來介紹書報。文摘每一篇都是從一本書的某一篇裁下來的，
所以它本身就是一份現成的書報索引 —— 只是從期數進去，不是從書進去。
這頁把它反過來。

**這頁沒有書封，也不收錄任何信息內文。** 只有書目資料，讓文字說話。

規模：80 期、2,252 篇、666 本書、3,078 筆「篇 → 書」的引用。

## 三種用法

| 用法 | 做什麼 |
|------|--------|
| **讀一篇** | 預設畫面。整頁只有一篇：分類、卷期、篇題、讀經、出自哪本書第幾篇，每個出處兩條連結（到書房看這本書／讀這一篇）。按「換一篇」再來一篇，可先用分類或卷期篩選 |
| **依書** | 反查。一本書列出被哪幾期、哪幾篇引用，依真理／生命／事奉／福音／唱詩人分組。一本書能列出十幾個題目的時候，那本書在講什麼就不必再介紹了 |
| **依期** | 卷期 → 五個分類 → 篇題，每一篇標著它出自哪本書。點篇題就跳到「讀一篇」 |

網址 hash 可以分享：`#1101.no3-2` 某一篇、`#b.2418` 某一本書、`#i.1101` 某一期。

> 「換一篇」只抽**對到書**的篇（1,676／2,252）。這頁的用處是從一個題目走到一本書，
> 抽到沒有出處書的篇就走不過去了 —— 那多半是「唱詩人」裡只連音檔的詩歌（該分類 46% 沒有出處書）。
> 那些篇還是可以從「依期」點進來看。

## 資料是哪裡來的

| 來源 | 用途 | 網址格式 |
|------|------|----------|
| [職事文摘多媒體資源](https://ministrydigest.twgbr.org/) | 卷期、分類、篇題、頁碼、出處書名篇章、讀經經節、書號 | 索引頁 `8026-{卷2碼}{期2碼}/`；出處頁 `8026-{卷期}/webpg/{n-n-n}.html` |
| [臺灣福音書房](https://www.twgbr.org.tw/) | 購書連結 | `products?query={書號}` |

`8026` 是固定前綴，不隨年份換。實測存在的卷期：**卷一只有 01、05–08**，卷二到卷十各八期，
卷十一出到第三期，共 **80 期**。五個分類（真理／生命／事奉／福音／唱詩人）
從卷一第一期到現在完全一致，`#no1`–`#no5` 固定對應。

**書號是書房自己標好的**，不是猜的 —— 每個出處頁底部「購書」按鈕的 onclick 裡就寫著：

```html
<li id="nbtab5" onclick="location.href = 'https://www.twgbr.org.tw/products?query=2418'">購書</li>
```

這是整件事的樞紐。有了它，「篇題 → 書」的對應才是準的，才能反過來做「依書」。

## 為什麼不即時抓

和 `crossref/`、`version-diff/`「repo 裡不存任何資料、全部即時抓」的做法**不一樣**，兩個原因：

1. **那站沒有 API**，是一包靜態 HTML（jQuery Mobile），沒有任何 JSON 端點。
2. **沒有 CORS。** 索引頁和出處頁都不回 `Access-Control-Allow-Origin`（實測過），
   瀏覽器的跨網域請求會被擋掉，前端沒辦法即時抓。

```
$ curl -D - -o /dev/null -H "Origin: https://soaring0616.github.io" \
    https://ministrydigest.twgbr.org/8026-1101/webpg/3-2-2.html
HTTP/1.1 200 OK
Content-Type: text/html
（沒有 access-control-allow-origin）
```

所以索引在建置時抓好、存成 JSON 進 repo。要繞過 CORS 只有兩條路：
靠公開 CORS proxy（多一個會壞的第三方、每次開頁都慢），
或自架 Cloudflare Worker 之類的轉送（多一個要維護的東西，而且等於替對方重新供稿）。
文摘一年只出八期，「即時」換不到任何東西，所以兩條都沒走 —— 改成定時補新期（見下）。

存的是**書目資料**（卷期、分類、篇題、讀經經節、出處書名篇章、書號），
性質和經文不一樣；**信息內文一個字都沒有存**，內文一律連回原站與書房的書。
原頁只掛「@2026 臺灣福音書房」，站上沒有授權條款，所以界線畫在書目層。

> 注意出處頁（`webpg/*.html`）**不是摘要，是信息全文**。頁尾還有「講於四月二十日」這種落款。
> 要加介紹文字的話請自己寫，不要從那裡搬。

## 自動補新的一期

`.github/workflows/digest-refresh.yml` 每月探一次：有新的一期就只抓那一期、
commit 回 `main`（接著 `deploy.yml` 會自然重新發布），沒有就什麼都不做。
也可以在 Actions 頁面手動觸發，並指定期數。要停掉就把那個 workflow 檔刪了。

`--discover` 是從索引裡最新的一期往前探（第八期之後跳下一卷第一期），
遇到不存在的就停，所以**中間缺號的情況要用 `--only` 補**。

## 重新產生索引

```bash
cd digest
python3 scripts/build_digest_index.py                  # 全部 80 期（約 4,600 個出處頁，十幾分鐘）
python3 scripts/build_digest_index.py --discover       # 只抓比索引更新的期數（定時任務用的）
python3 scripts/build_digest_index.py --only 1104      # 只補指定的一期
python3 scripts/build_digest_index.py --no-inner       # 只抓索引頁，不取書號（快，但沒有「依書」）
python3 scripts/build_digest_index.py --refresh        # 忽略快取重抓
```

只用標準函式庫，不需要裝套件。抓過的頁面存在 `digest/.cache/`（已 gitignore），
重跑時不會再去煩對方的站。預設 5 條連線。
`--only` 和 `--discover` 會**併回**現有索引，不會蓋掉其他期。

> 對方站上有 **10 個出處頁是 404**（他們自己的斷連結，都在「唱詩人」那段，
> 像 `5-2-2-1.html`、`5-2-7.html`）。抓取器對單頁失敗是容錯的，
> 那一筆就沒有書號，其餘照舊。

## 結構

純靜態、無建置步驟（和 `crossref/`、`version-diff/` 一樣，`deploy.yml` 不用改）：

| 檔案 | 職責 |
|------|------|
| `scripts/build_digest_index.py` | 抓取與剖析，產生 `data/` 下的索引 |
| `scripts/smoke.js` | 煙霧測試，用 Rhino 把 `js/app.js` 跑起來走過三個畫面 |
| `data/index.json` | 輕索引：卷期 → 分類 → 篇題、頁碼、錨點、書號 |
| `data/books.json` | 一本書一筆：書號、書名、被哪幾期哪幾篇引用（只存「期＋錨點」） |
| `data/issues/{期}.json` | 該期每篇的出處書名、篇章、讀經經節 |
| `js/app.js` | 三種用法的介面、篩選、網址 hash、分期載入 |

**為什麼拆成三組檔**：一開始做成一大包，`issues.json` ＋ `books.json` 兩個檔 gzip 後共 692K，
對一個安靜的文字頁太重，而且 `books.json` 整份都是重複資料。
現在開頁只讀輕索引與書單（gzip **86K**），點到哪一期才抓那一期（單檔最大 40K、gzip 約 8K）。
副作用是 `--only 1104` 只會動到一個期檔，git diff 乾淨。

剖析是沿著索引頁的 `data-role="page"` 區塊和 `#錨點` 遞迴走下去的，
因為「唱詩人」那段比其他分類多一層（每週一詩 → 各首詩）。
一個節點底下直接掛著出處頁就算「一篇」；「新詩分享」直接連音檔、沒有子節點，自己算一篇。
`scripts/build_digest_index.py` 的 `flatten()` 和 `js/app.js` 的 `prepare()`
必須攤出一樣的結果（錨點是兩邊的共同鍵），改一邊要改另一邊。

## 本機預覽與測試

```bash
cd digest && rhino scripts/smoke.js     # 39 項：三個畫面 + hash + 換一篇 ×300

cd .. && python3 -m http.server 8000
# http://localhost:8000/digest/
```
