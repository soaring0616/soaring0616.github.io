# 基督徒書報介紹

<https://soaring0616.github.io/digest/>

希望幫助基督徒在**生命**與**事奉**上有更明確的指引。

選一個分類 —— 真理／生命／事奉／福音／詩歌 —— 一次給你**九段**書報裡的內容。
哪一段說到你，就從那一段下面去**試讀**整篇，或看那本書的**購買資訊**。

材料出自臺灣福音書房的[《職事文摘》](https://ministrydigest.twgbr.org/)八十期。
文摘每一篇都是從一本書的某一篇裁下來的，所以它本身就是一份現成的書報索引 ——
只是從期數進去，不是從書進去。這頁把它反過來，而且用內容本身說話，不用書封。

規模：**3,861 段**（每一段都有書號可以連到購買資訊）、666 本書、80 期。

## 分類

| 分頁 | 段數 |
|------|------|
| 真理 | 938 |
| 生命 | 1,104 |
| 事奉 | 725 |
| 福音 | 461 |
| 詩歌 | 633 |

> 頁面上叫「詩歌」，資料裡沿用文摘自己的分類名「唱詩人」（`SECTION_SLUG` 對照 `no1`–`no5`）。

另外兩個入口（分頁列右邊，刻意做得安靜）：

- **依書** —— 一本書被哪幾篇引用過，依五個分類分組。一本書能列出十幾個題目的時候，那本書在講什麼就不必再介紹了
- **依期** —— 照卷期看目錄，每一篇標著它出自哪本書

網址 hash 可以分享：`#c.no1` 某個分類、`#b.2418` 某一本書、`#i.1101` 某一期。

## 卡片上那一段是怎麼來的

`pick_excerpt()` 從出處頁挑**一段**，目標是 140–165 字且**句子完整**，
實際結果 99% 落在這個範圍、平均 150 字。會跳過：

- 經文引用開頭的段落（「馬太福音十八章二十節：」）
- 條列項（（一）（二）…、「第一，」）
- 整段幾乎都是『…』引文的（占比 > 45%）
- 落款（「講於四月二十日」）與讀經行

以連接詞開頭（「所以」「因此」…）的扣分，因為讀起來像從中間截的；
超過 165 字的就在最後一個句末符號切斷，切不出 112 字以上就放棄那一頁。

**界線**：一頁只取一段，一定附書名篇名，一定有回原站的連結，repo 裡不存全文。
出處頁（`webpg/*.html`）其實是**信息全文**，不是摘要 —— 要整篇請走「試讀」。
版權屬臺灣福音書房。

## 詩歌的連結

詩歌那一類的卡片多一條連到 [hymnal.net](https://www.hymnal.net/) 的連結：

- **對得上首數的**（106 張卡）→ 直接連那一首，`https://www.hymnal.net/zh/hymn/{ch|ts|c}/{首數}`
- **對不上的** → 連 hymnal.net 的標題搜尋，`https://www.hymnal.net/zh/search/all/all/{標題}`

首數是拿 `hymn-picker/public/data/hymn_index.json`（由蒙特利公園市召會的目錄頁建的）
的標題去對的，能對上 762 個標題。**對不上的占多數**，因為那份目錄裡
**大本那 780 筆只有號碼範圍、沒有標題**，只有補充本（437）與兒童（330）有標題。

hymnal.net 自己沒有可用的對照表：`/zh/song-index/ch` 與 `/ts` 都是 404，
目錄與瀏覽頁（`/zh/catalog`、`/zh/song-categories/*`）是**前端渲染的空殼**
（去標籤後只剩 795 字可見文字、0 個詩歌連結），sitemap 只有網址沒有標題。
要補齊只能去爬幾千頁歌詞頁，那正是它 `robots.txt` 擋的事（`complete-lyrics-archive`
被 Disallow），所以沒做。日後若找到一份帶標題的大本目錄，只要餵進
`hymn_index.json` 就會自動對上。

## 資料是哪裡來的

| 來源 | 用途 | 網址格式 |
|------|------|----------|
| [職事文摘多媒體資源](https://ministrydigest.twgbr.org/) | 卷期、分類、篇題、頁碼、出處書名篇章、讀經經節、書號、節錄 | 索引頁 `8026-{卷2碼}{期2碼}/`；出處頁 `8026-{卷期}/webpg/{n-n-n}.html` |
| [臺灣福音書房](https://www.twgbr.org.tw/) | 購買資訊 | `products?query={書號}` |
| [hymnal.net](https://www.hymnal.net/) | 詩歌 | `zh/hymn/{ch\|ts\|c}/{首數}`、`zh/search/all/all/{標題}` |

`8026` 是固定前綴，不隨年份換。實測存在的卷期：**卷一只有 01、05–08**，卷二到卷十各八期，
卷十一出到第三期，共 **80 期**。五個分類從卷一第一期到現在完全一致，`#no1`–`#no5` 固定對應。

**書號是書房自己標好的**，不是猜的 —— 每個出處頁底部「購書」按鈕的 onclick 裡就寫著：

```html
<li id="nbtab5" onclick="location.href = 'https://www.twgbr.org.tw/products?query=2418'">購書</li>
```

這是整件事的樞紐。沒有書號的段落**不收**（連不到購買資訊，這頁的用處就斷了），
所以 4,490 段裡只留下 3,861 段。

## 為什麼不即時抓

和 `crossref/`、`version-diff/`「repo 裡不存任何資料」的做法**不一樣**，兩個原因：

1. **那站沒有 API**，是一包靜態 HTML（jQuery Mobile），沒有任何 JSON 端點。
2. **沒有 CORS。** 索引頁和出處頁都不回 `Access-Control-Allow-Origin`（實測過），
   瀏覽器的跨網域請求會被擋掉。

要繞只有靠公開 CORS proxy（多一個會壞的第三方、每次開頁都慢）或自架轉送
（多一個要維護的東西，而且等於替對方重新供稿）。文摘一年只出八期，「即時」換不到
任何東西，所以改成定時補新期。

## 自動補新的一期

`.github/workflows/digest-refresh.yml` 每月探一次：有新的一期就只抓那一期、
commit 回 `main`（接著 `deploy.yml` 會自然重新發布），沒有就什麼都不做。
也可以在 Actions 頁面手動觸發並指定期數。要停掉就把那個 workflow 檔刪了。

`--discover` 從索引裡最新的一期往前探（第八期之後跳下一卷第一期），
遇到不存在的就停，所以**中間缺號的情況要用 `--only` 補**。

## 重新產生索引

```bash
cd digest
python3 scripts/build_digest_index.py                  # 全部 80 期（約 4,600 個出處頁，十幾分鐘）
python3 scripts/build_digest_index.py --discover       # 只抓比索引更新的期數（定時任務用的）
python3 scripts/build_digest_index.py --only 1104      # 只補指定的一期
python3 scripts/build_digest_index.py --no-inner       # 只抓索引頁（快，但沒有節錄也沒有書號）
python3 scripts/build_digest_index.py --refresh        # 忽略快取重抓
```

只用標準函式庫，不需要裝套件。抓過的頁面存在 `digest/.cache/`（已 gitignore），
重跑時不會再去煩對方的站。預設 5 條連線。
`--only` 和 `--discover` 會**併回**現有索引，不會蓋掉其他期；
`data/cards/` 和 `data/books.json` 每次都從 `data/issues/` 全部重建。

> 對方站上有 **10 個出處頁是 404**（他們自己的斷連結，都在詩歌那段，
> 像 `5-2-2-1.html`、`5-2-7.html`）。抓取器對單頁失敗是容錯的，那一筆就沒有卡片。

## 結構

純靜態、無建置步驟（和 `crossref/`、`version-diff/` 一樣，`deploy.yml` 不用改）：

| 檔案 | 職責 |
|------|------|
| `scripts/build_digest_index.py` | 抓取、剖析、挑節錄，產生 `data/` 下的索引 |
| `scripts/smoke.js` | 煙霧測試，用 Rhino 把 `js/app.js` 跑起來走過五個分類與兩個入口 |
| `data/cards/manifest.json` | 每個分類有幾段、切成幾塊 |
| `data/cards/{分類}-{塊}.json` | 一塊 120 段卡片（節錄、書名篇名、書號、試讀網址、詩歌連結） |
| `data/index.json` | 輕索引：卷期 → 分類 → 篇題、頁碼、錨點、書號 |
| `data/books.json` | 一本書一筆：書號、書名、被哪幾期哪幾篇引用 |
| `data/issues/{期}.json` | 該期每篇的出處書名、篇章、讀經經節、節錄 |
| `js/app.js` | 五個分類的卡片、依書、依期、網址 hash、分塊載入 |

**載入量**：開頁只讀 `cards/manifest.json`（4K）加一塊卡片（gzip 約 27K）。
頁面一次只顯示九段，所以每個分類切成 120 段一塊，點一次抓一塊；
按三輪「再換九段」才再抓一塊，所以越看越廣，又不會一開頁就把整個分類
（最大 275K gzip）拉下來。「依書」「依期」要用到完整索引，點到那兩個分頁才讀。

剖析是沿著索引頁的 `data-role="page"` 區塊和 `#錨點` 遞迴走下去的，
因為詩歌那段比其他分類多一層（每週一詩 → 各首詩）。
一個節點底下直接掛著出處頁就算「一篇」；「新詩分享」直接連音檔、沒有子節點，自己算一篇。
`build_digest_index.py` 的 `flatten()` 和 `js/app.js` 的 `needIndex()`
必須攤出一樣的結果（錨點是兩邊的共同鍵），改一邊要改另一邊。

## 本機預覽與測試

```bash
cd digest && rhino scripts/smoke.js     # 36 項：五個分類、卡片兩條連結、依書、依期、hash

cd .. && python3 -m http.server 8000
# http://localhost:8000/digest/
```
