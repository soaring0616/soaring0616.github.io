# 版本對讀

<https://soaring0616.github.io/version-diff/>

把**聖經恢復本**與**和合本**並排，以「字」為單位比對，標出兩版不一樣的地方；
可以依卷書掃描整卷列出所有差異，每一節都能**在頁面上直接展開原文**，
滑過每個原文字就看到詞性、語法分析與解釋。

起因是和聖徒一起讀詩篇 76:11 時發現兩版對不起來，以弗所書 4:15 也不一樣，
想有個地方可以一卷一卷把差異整理下來。

## 四種用法

| 用法 | 做什麼 |
|------|--------|
| **對讀這一章** | 選一卷一章，兩欄並排。只有和合本有的字標成橘色，只有恢復本有的字標成藍色 |
| **原文逐字** | 每一節按「原文逐字」就在頁面上展開希臘文／希伯來文。滑過或用鍵盤移到任一個字，顯示字根、詞性、語法分析和中文解釋；點下去查完整原文字典（中文與英文詞條可切換） |
| **掃描整卷** | 整卷每章都比一遍，依章列出所有有差異的節與差異片語。這是「依卷書列出不一樣的地方」的主力 |
| **我的記錄** | 自己讀到想留下來的觀察，寫在 `data/diffs.js`，會掛在對應的節上 |

兩個選項：**只顯示有差異的節**（預設開）、**忽略標點差異**（預設開）。
兩版的標點習慣本來就不同，不忽略的話整章都會被標成有差異。

網址 hash 可以分享：`#49.4` 開以弗所書第 4 章，`#49.4.15` 直接跳到 4:15
（格式是 `書卷號.章.節`，書卷號見 `js/books.js`）。

## 原文是怎麼來的

信望愛的 `qp.php`（字彙分析）一次就把一節的每個原文字連同**中文解釋**都給了，
所以滑過去看解釋不需要再發請求。點一個字才會去 `sd.php`（原文字典）拿完整詞條，
中文與英文都有。

舊約是希伯來文，會自動切成右起（RTL）並換成希伯來文字型。

> 信望愛另外兩支中文字典 `sbdag.php`（浸宣希臘文）與 `stwcbhdic.php`（浸宣希伯來文）
> 在它的 API 說明裡註明**僅授權該站使用**，所以這裡刻意不碰，只用 `sd.php`。

## 記錄自己的觀察

頁面上每一節都有「**複製記錄範本**」按鈕，按下去會把那一節的書卷號、章節
和兩邊的差異片語整理成一段，貼進 `data/diffs.js` 的陣列裡，填上 `tag`／`note`／`original` 即可。
存檔重新整理就會出現，沒有建置步驟。

經文本身不要寫進 `data/diffs.js` —— 經文是現場去抓的，這個檔案只放自己的話。

## 資料來源

| 來源 | 用途 | 網址／端點格式 |
|------|------|----------------|
| [網上聖經恢復本](https://www.recoveryversion.com.tw/) | 恢復本經文與註解（公開 API，`crossref/` 也是用這組） | `api/getVerses`、`api/getFootnotes`；逐章頁面 `verse/{書卷號}/{章}` |
| [信望愛](https://bible.fhl.net/) | 和合本經文、**原文字彙分析**、**原文字典** | `json/qb.php`、`json/qp.php`、`json/sd.php`；並排原文的閱讀頁見下 |
| [biblehub](https://biblehub.com/) | 原文逐字對照與英文各譯本 | `interlinear/{slug}/{章}-{節}.htm` |
| [bibleread.online](https://bibleread.online/bible/) | 英文恢復本 | `bible/{slug}/{章}/#{節}` |
| [cut.ibibles.net](https://cut.ibibles.net/) | 另一個和合本線上版 | `{NNN}{Book}.htm#{NNN}-{章}`，只到整章 |

「信望愛原文」按鈕開的是和合本並排原文的閱讀頁：
新約 `VERSION1=unv&VERSION92=gnt6&VERSION14=interubs4`（和合本＋UBS6 希臘文＋希中逐字對照），
舊約 `VERSION1=unv&VERSION2=bhs`（和合本＋馬索拉原文）。
`VERSION` 後面的編號實測 2 與 92 都收，伺服器似乎不在意用哪個數字；舊約沒有對應的逐字對照版本代號。

所有經文、原文與字典內容都在開頁面時即時取得，以 localStorage 快取 30 天，
**repo 裡不存放任何經文或字典資料**，和 `crossref/` 同一套做法。
恢復本經文版權屬台灣福音書房；原文分析與字典出自信望愛。

## 結構

純靜態、無建置步驟（和 `crossref/` 一樣，CI 不用改）：

| 檔案 | 職責 |
|------|------|
| `js/books.js` | 66 卷書卷表 + 五個外部識別碼（`fhl` 中文縮寫／`engs` 英文簡寫／`hub`／`cut`／`bro`） |
| `js/sources.js` | 各來源的逐節網址組法。對方改版只要改這裡 |
| `js/diff.js` | 逐字 LCS 比對，輸出 same／del／ins 段落；可忽略標點 |
| `js/api.js` | 恢復本經文註解、和合本經文、原文字彙分析、原文字典，含快取 |
| `data/diffs.js` | 自己寫的記錄（手動維護） |
| `js/app.js` | 介面：對讀、原文逐字與字典、掃描整卷、記錄面板、網址 hash |

`js/books.js` 的 `fhl` 與 `engs` 兩欄都照信望愛自己的 `json/listall.html` 對過，
包含 1/2/3 John 是「約一／約二／約三」、數字書卷的英文簡寫帶一個空格（`1 Sam`、`1 Cor`）。

## 關於標色的脾氣

比對是以「字」為單位做最長共同子序列（LCS）。中文沒有詞界，所以兩版翻法差很多的時候，
共同的字可能散落在句子各處，標色看起來會比較碎。例如弗 4:15 那半句，
兩邊共有的是「惟」「愛」「實」三個字，中間差異的部分各自標色，
讀起來是「惟 ⟨用→在⟩ 愛 ⟨心說誠→裏持守著真⟩ 實」。
骨架還是看得出來，但它不會幫你斷詞。真正要判斷意思，展開原文逐字看。

演算法本身的不變量有測過：每一欄把 same／標色／自己的標點接回去，
一定等於該版本原本的經文，不會漏字或多字。

## 已知待確認

- **CORS 尚未在瀏覽器實測。** 和合本經文、原文字彙分析、原文字典都是瀏覽器直接向
  信望愛取用的；若對方未開放跨網域，這幾項會失敗。頁面對每一項都有個別的容錯：
  和合本失敗時只顯示恢復本一欄並提示，原文失敗時改提供「改在信望愛開啟」的連結，
  不會整頁壞掉。恢復本那組 API 已知可用（`crossref/` 在用）。
- **恢復本的 `verse/{書卷號}/{章}` 逐章網址格式由站主提供，無法從伺服器回應驗證**
  —— 該站是前端渲染，任何路徑都回 HTTP 200 和同一份空殼，連 `/verse/999/999` 也一樣，
  所以對與錯的路徑從外面看起來完全相同。
- 舊約沒有找到可用的逐字對照版本代號，所以「信望愛原文」在舊約只並排馬索拉原文；
  頁面上的「原文逐字」不受影響，舊約一樣有逐字分析與字典。
